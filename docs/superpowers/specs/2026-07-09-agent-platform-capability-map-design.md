# 智能体平台功能全景图

> 日期：2026-07-09  
> 状态：已对齐（配置态 / 运行态分层，先对内后对外）  
> 类型：功能清单与边界说明（非实现规格）

## 1. 目标与约束

### 1.1 目标

整理企业级智能体平台的功能全景，明确模块边界、开放问题结论，以及 **必做 / 可选 / 后期** 阶段，供对内对齐与排期。

### 1.2 已确认前提

| 项 | 结论 |
|----|------|
| 交付形态 | 先对内研发平台，再对外开放业务入口 |
| 应用 vs 数字员工 | **分开**：应用是能力单元；数字员工是组织协作产品实体 |
| 组织边界 | **两层**：租户（计费/强隔离）+ Workspace 协作空间 |
| 文档形态 | 按生命周期分层的功能全景图（非控制面架构拆分、非角色手册） |

### 1.3 阶段定义

- **必做（MVP）**：对内可用——资源配置、单智能体配置发布、基础部署、Chatbox/API、调用/Trace/Token、三轨权限基础
- **可选（V1）**：编排、Skills Hub 完整、Swagger→MCP、评测、分层记忆、定时任务、数字员工、Plugin
- **后期**：精细路由与按需加载、成本精细治理、行级数据权限、评测发布门禁、数字员工值班等

### 2.1 关键概念边界

| 概念 | 定义 | 归属 |
|------|------|------|
| **租户** | 计费、管理员、强隔离边界 | L0 |
| **Workspace（协作空间）** | 租户下的项目/团队空间，资源默认可见范围 | L0 |
| **SessionWorkspace** | 某次运行产生的工作目录/文件沙箱（避免与协作空间同名混淆） | L3 |
| **应用（Agent App）** | 可版本化的智能体配置实体 | L2 |
| **数字员工** | 面向组织协作的产品实体，绑定 1..N 个已发布应用 | L4 |
| **资源** | 模型/技能/MCP/知识库/工具等可被应用引用的资产 | L1 |

## 3. L1 资源配置

原则：资产可复用、可版本化、可授权；应用只引用；**发布时可快照锁定资源版本**。

### 3.1 模型管理 — 必做

| 能力 | 说明 | 阶段 |
|------|------|------|
| 模型接入 | Provider / 模型 ID / 能力标签（chat、vision、embedding、rerank、function-call 等） | 必做 |
| 接入通道 | **默认经 NewAPI（或同类网关）**做路由、鉴权、计量；保留直连 Provider 作逃生通道 | 必做 |
| 可见性 | 租户 / Workspace / 指定应用 | 必做 |
| 权限分配 | 谁可配置、谁可在应用中选用 | 必做 |
| 能力选择 | 按能力过滤；应用配置时校验能力匹配 | 必做 |
| 模版套件 | 预设参数包（temperature、max_tokens、超时、JSON mode 等） | 可选 |
| 成本控制 | 单价元数据、预算告警、租户/应用/用户限流与配额；超额拒绝或降级 | 必做（基础）→ 后期（精细） |
| 健康与降级 | 探活、熔断、同能力 fallback 链 | 可选 |

**是否完全依赖 NewAPI？**  
不完全依赖，但默认依赖。平台管目录、权限、套件、配额策略与应用绑定；NewAPI 管密钥、上游路由、计量票据；平台消费用量回调做二次聚合。

### 3.2 技能管理 — 必做（Hub 完整能力 V1）

**A. Skills Hub（资产中心）**

- 创建 / 上传 / 导入（git、zip、市场）
- 同步（Hub ↔ 运行环境）
- 版本管理（semver、changelog、兼容声明）
- 安全校验：MVP 为权限声明 + 人工审核标记；自动扫描后期
- 依赖声明（工具、MCP、环境变量、系统包）

**B. 运行时安装（对接 AgentOS）**

- 同步到节点；按应用发布触发安装
- 运行前 ensure-installed
- 更新策略：跟随 latest / 锁定版本 / 灰度

**C. 技能依赖的工具权限**

- 技能声明所需工具能力
- 应用启用技能时合并上收到应用工具权限集，需确认
- 运行时：`应用授权 ∩ 技能声明 ∩ 执行身份`

### 3.3 工具管理 — 独立模块

**工具 ≠ 技能 ≠ MCP。**

| 概念 | 含义 | 工具管理职责 |
|------|------|--------------|
| 内置工具 | 平台原子能力（读文件、HTTP、代码执行、检索等） | 建档、开关、schema、风险等级 |
| MCP 工具 | 来自 MCP Server 的 tools | 统一检索/授权视图 |
| 技能内工具 | 技能包暴露的操作 | 聚合展示，不重复建档 |

工具管理模块：

1. 统一工具目录（跨内置 / MCP / 技能）
2. 风险分级（只读 / 写 / 外部副作用 / 高危）
3. 授权策略模板
4. 运行时策略（超时、重试、并发、人机确认）
5. 高危审计钩子

MVP：内置工具目录 + 应用级启用列表；统一目录与风险分级放 V1。

### 3.4 MCP 管理 — 必做（生成器 V1）

| 能力 | 说明 | 阶段 |
|------|------|------|
| MCP Server 实例 | 创建/启停；stdio / SSE / HTTP | 必做 |
| 从内部应用生成 | 选应用 → 选接口 → Swagger/OpenAPI → 生成 tools 与配置 | 可选（V1） |
| 鉴权透传 | 平台代持密钥、运行时透传用户 Token、Workspace 凭证、AccessKey 映射 | 必做（至少代持 + 透传） |
| 接入与调试 | tools/list、单 tool 试跑、schema/连通性校验 | 必做 |
| 可见性与授权 | 租户 / Workspace / 应用 | 必做 |
| 变更检测 | 上游破坏性变更告警 | 后期 |

### 3.5 知识库管理 — 必做（对接 RAGFlow）

| 能力 | 说明 | 阶段 |
|------|------|------|
| 对接 | 绑定 RAGFlow 实例/知识库；同步元数据 | 必做 |
| 查看 | 库/文档列表、检索试跑 | 必做 |
| 应用绑定 | 引用哪些库、检索参数（topK、阈值、重排） | 必做 |
| 权限 | **需要。** 平台做库级授权（谁能绑定/在某 Workspace 使用）；文档级 ACL 优先交给 RAGFlow | 必做（库级） |
| 文档代管上传 | 能不接管就不接管 | 可选 |

### 3.6 资源层共性

- 归属：租户 + 可选 Workspace
- 可见性：私有 / 空间内 / 租户内 / 平台公共
- 引用计数与删除保护
- 应用发布时锁定资源版本
- 创建与授权变更审计

## 4. L2 智能体应用配置与发布

数字员工不在此配置，仅在 L4 绑定已发布应用。

### 4.1 分类管理 — 必做

租户内树形/标签分类；应用挂分类；分类级授权可选。

### 4.2 单 Agent 配置 — 必做

| 配置块 | 内容 | 阶段 |
|--------|------|------|
| 基础信息 | 名称、描述、图标、分类、负责人、标签 | 必做 |
| 系统提示词 | 主 Prompt、变量、草稿多版本 | 必做 |
| 模型 | 主模型 + fallback、套件、参数覆盖 | 必做 |
| 输入 | 模态、参数 schema、附件限制 | 必做 |
| 输出 | 文本 / JSON schema / 流式、后处理 | 必做 |
| 工具 | 内置工具、Skills（锁版本）、MCP 及 tool 子集、调用轮数/并行 | 必做 |
| 知识库 | 绑定与检索参数；注入 prompt 或作 tool | 必做 |
| 记忆 | 见下表 | 必做（窗口）→ V1（分层） |
| 运行控制 | 超时、步数、重试、并发、高危人机确认 | 必做 |
| 返回/回调 | webhook、写回业务系统 | 可选 |
| 安全策略摘要 | 出网等约束 | 可选 |
| 评测绑定 | 默认数据集/评测器 | 后期 |

**记忆配置（应用侧开关）：**

| 层级 | 含义 | 阶段 |
|------|------|------|
| 窗口记忆 | 上下文窗口 / token 截断 | 必做 |
| 压缩记忆 | 超窗摘要压缩 | 可选 |
| 场景记忆 | 单次任务中间状态 | 可选 |
| 事实记忆 | 可检索结构化事实 | V1 |
| 长期记忆 | 跨会话（应用×用户 或 数字员工×用户） | V1 |
| 按入口关闭 | 如 API 无状态、Chatbox 开窗口 | 必做 |

### 4.3 版本、环境与发布 — 必做

| 能力 | 说明 | 阶段 |
|------|------|------|
| 草稿 / 已发布 | 编辑不影响线上 | 必做 |
| 语义化版本 | 不可变快照（含资源版本锁定） | 必做 |
| 环境 | MVP：draft vs prod；V1：dev/staging/prod | 必做 → V1 |
| 发布门禁 | 必填校验、工具权限确认；评测通过后期 | 必做 → 后期 |
| 回滚 | 回滚到历史版本 | 必做 |
| 变更说明 / 审批 | changelog、对接审批流 | 可选 |

### 4.4 部署节点绑定 — 必做（精细 V1）

指定节点池/标签；MVP 用租户默认节点池。

### 4.5 多智能体编排 — 可选（V1）

Supervisor / 流水线 / 并行汇聚 / 图编排；编排本身作为应用类型版本化。MVP 先单 Agent。

### 4.6 关系

```text
应用(版本) ──引用──► 模型 / 技能 / 工具 / MCP / 知识库
    ├──发布──► 运行时加载到节点
    ├──被入口调用──► Chatbox / API / Plugin / 定时任务
    └──被绑定──► 数字员工（1 数字员工 : N 应用版本）
```

## 5. L3 部署与运行时基础设施

L2 声明意图，L3 落实调度与隔离。

### 5.1 机器 / 节点管理

| 能力 | 说明 | 阶段 |
|------|------|------|
| 节点注册 | ID、地址、标签、容量、状态 | 必做 |
| 节点池 | 按租户或用途分组 | 必做 |
| 心跳与探活 | 失联摘除 | 必做 |
| 应用加载清单 | 节点上已装应用版本/技能 | 必做 |
| 按需加载 | 冷启动、预热、淘汰 | 可选（V1） |
| 指定部署 | 应用 ↔ 节点/标签 | 可选（V1） |

**路由（必做基础版）：**

- 按 `应用 ID + 环境 + 策略` 选节点
- 优先级：指定节点 > 标签匹配 > 默认池；同池负载/会话粘滞
- 同一 `session_id` 尽量粘滞（本地 SessionWorkspace）
- 可重试错误换节点；业务拒绝不重试

### 5.2 沙箱管理 — 必做

指定的是 **沙箱策略/规格档位**（如 lite / standard / networked），不是默认绑死某台机器。

| 能力 | 说明 | 阶段 |
|------|------|------|
| 沙箱集群注册 | 容器/微 VM/执行器 | 必做 |
| 规格 | CPU/内存/网络/超时/出网 | 必做 |
| 分配策略 | 按应用策略选规格；按会话创建/复用；空闲回收 | 必做 |
| 与工具关系 | 代码执行、写文件、浏览器等必须走沙箱 | 必做 |
| 取证快照 | 合规场景 | 后期 |

### 5.3 SessionWorkspace — 必做

| 能力 | 说明 | 阶段 |
|------|------|------|
| 创建时机 | 会话开始或首次写文件时懒创建 | 必做 |
| 内容 | 附件、中间产物、技能工作目录 | 必做 |
| 生命周期 | TTL、结束归档/删除、容量配额 | 必做 |
| 亲和性 | 与路由粘滞配合；迁移可搬迁或只读重建 | V1 |
| 权限 | 仅会话执行身份可读写 | 必做 |

### 5.4 Agent 执行权限 — 必做

独立于「谁能打开应用」：

```text
调用者身份
  ∩ 应用使用权限
  ∩ 应用已启用工具/技能/MCP 子集
  ∩ 技能声明权限
  ∩ 沙箱网络/文件系统策略
  ∩ 目标系统鉴权（MCP 透传）
  → 实际可执行动作
```

| 维度 | 控制什么 | 阶段 |
|------|----------|------|
| 工具执行 | 可调 tool、是否人机确认 | 必做 |
| 数据出域 | 外网、域名、附件出站 | 必做 |
| 代表谁执行 | 用户 / 应用服务账号 / 数字员工 | 必做 |
| 资源配额 | token、工具次数、沙箱时长 | 必做 |
| 临时提权 | 审批后、有过期 | 后期 |

## 6. L4 运行入口与数字员工

### 6.1 统一原则

- 应用是能力单元；入口是触达形态
- 入口决定调用者身份，再套 L3 执行权限
- 所有入口统一写调用记录 / Trace / Token（带 `entry_type`）

### 6.2 Chatbox — 必做

会话、应用选择（按使用权限）、附件、流式；人机确认与调试态可选。

### 6.3 API / AccessKey — 必做

同步/流式 Invoke；Key 范围（应用/环境）、过期轮换；限流配额；webhook/OpenAPI 可选。

### 6.4 Plugin — 可选（V1）

嵌入业务系统的轻量组件；复用应用 + SSO/业务票据换身份。

### 6.5 定时任务 — 可选（V1）

Cron/间隔；绑定已发布应用 + 输入模板；服务账号或数字员工身份；结果通知与失败重试。可被数字员工值班引用，但不等于数字员工。

### 6.6 数字员工 — 独立实体（V1）

**定位：** 组织协作的岗位化 Agent，不是应用别名。

```text
数字员工
  ├── 组织属性：部门、岗位、职责、负责人
  ├── 渠道：钉钉（主）/ 其它 IM（后期）
  ├── 能力绑定：1..N 个已发布应用（可按意图路由）
  ├── 运行身份：独立服务身份 + 可选代理用户
  ├── 协作：值班、交接、人工接管、审批
  └── 记忆：默认「数字员工 × 用户/群」维度
```

| 能力 | 说明 | 阶段 |
|------|------|------|
| 档案与生命周期 | 与应用发布解耦 | V1 |
| 钉钉接入 | 机器人、事件、卡片 | V1 |
| 应用绑定与路由 | 单应用或多应用分发 | V1 |
| 独立使用授权 | 能用某应用 ≠ 能作为该数字员工对外服务 | V1 |
| 人工接管 | 升级人工、转交 | V1 |
| 值班/通讯录联动 | 工作时间、可见范围 | 后期 |

**钉钉与应用是否分开？**  
分开。钉钉配置挂在数字员工（或渠道连接器）上，不写入应用配置。

### 6.7 入口对照

| 入口 | 独立实体 | MVP | 典型调用者 |
|------|----------|-----|------------|
| Chatbox | 否 | 必做 | 内部用户 |
| API/AccessKey | 否 | 必做 | 系统集成 |
| Plugin | 否 | 可选 | 业务系统用户 |
| 定时任务 | 半独立 | 可选 | 服务账号 |
| 数字员工 | **是** | V1 | 组织成员（经钉钉等） |

## 7. L5 观测 · 记忆 · 评测 · 成本

### 7.1 调用记录 — 必做

租户/Workspace/应用/版本/入口/调用者/session/状态；输入输出可脱敏截断；关联 trace、数字员工、任务、AccessKey；按多维检索；保留策略可选。

### 7.2 Trace — 必做

会话 → Agent 步 → 模型/工具/检索/MCP；耗时与错误；时间线可视化；采样与 OTLP 导出可选/后期。

### 7.3 Token / 成本 — 必做

按应用、用户、智能体/步骤、入口聚合；结合 L1 单价估算；与 NewAPI 对账 V1；配额剩余与告警必做。

### 7.4 记忆存储 — 窗口必做，分层 V1

| 层级 | 范围键 | 阶段 |
|------|--------|------|
| 窗口 | `session_id` | 必做 |
| 压缩 | `session_id` | 可选 |
| 场景 | `session_id` + task | 可选 |
| 事实 | `app_id × user_id`（或数字员工维度） | V1 |
| 长期 | 同上，含遗忘策略 | V1 |

治理：用户可查看/删除关于自己的记忆；租户保留策略；数字员工记忆与应用记忆隔离。

### 7.5 评测 — 可选（V1）

数据集（可从调用记录加金标）、评测器（规则/模型/人工）、实验对比；发布门禁与自动回归后期。MVP 不做评测，但调用记录需能支撑日后进数据集。

### 7.6 告警与审计

运行告警（错误率/延迟/配额）与安全审计（配置/权限/高危执行）必做；成本预算告警可选。

## 8. L0 权限与平台底座

### 8.1 组织模型 — 必做

```text
平台 → 租户 → Workspace
         ├── 成员（SSO 用户/组映射）
         ├── 资源默认归属
         └── 可选映射数字员工组织单元
```

含租户管理、Workspace、SSO、服务账号。

### 8.2 三轨权限（核心结论）

| 轨道 | 管什么 | 典型问题 | 阶段 |
|------|--------|----------|------|
| **① 配置权限** | 后台与发布 | 能不能编辑/发布该应用？ | 必做 |
| **② 使用权限** | 能否触发运行 | 能不能在 Chatbox/API 调用？ | 必做 |
| **③ 执行权限** | 跑起来能碰什么 | 能不能调写接口/出网？ | 必做 |

三者同时满足才执行成功；拒绝需明确错误码。

### 8.3 配置权限 — 必做（依赖 SSO）

- 页面/菜单可见性
- 操作：创建/编辑/发布/下线/授权/删除（`role × resource_type × action`）
- 功能旗标（如能否创建 MCP）
- 数据范围：默认本 Workspace，跨空间显式分享

建议角色：平台超管、租户管理员、空间管理员、应用开发者、只读观察者、数字员工运营、成本审计员。发布审批可选。

### 8.4 使用权限 — 必做

- 应用访问（含环境：dev ≠ prod）
- 入口约束（可选）
- 数字员工访问（与应用 ACL 独立，V1）
- AccessKey（应用范围、环境、IP、配额）
- 资源 × Workspace 可见/可绑
- 接口行级数据权限后期（优先 MCP/业务 API，平台传身份）

### 8.5 执行权限策略归属

落在应用配置 + 运行时引擎 + 身份上下文 + 配额；控制台可用「权限预览」展示（可选）。不另造第四套权限系统。

### 8.6 其它底座

审计日志、配额包、平台默认设置必做；通知渠道可选。

### 8.7 运行路径判定

```text
请求 → SSO/AccessKey 鉴权
     → ② 使用权限（应用@环境）
     → 路由加载应用快照
     → ③ 执行权限（本步 tool/检索/出网）
     → ① 配置权限仅影响控制台，不走运行路径
```

## 10. 原开放问题结论摘要

| 问题 | 结论 |
|------|------|
| 是否完全依赖 NewAPI？ | 默认依赖，不完全锁死；平台管目录/权限/配额，NewAPI 管路由/密钥/计量 |
| 工具管理管什么？ | 统一目录、风险分级、授权模板、运行策略、审计；与技能/MCP 三分 |
| 知识库要不要权限？ | 要；平台库级授权，文档级优先 RAGFlow |
| 为智能体指定沙箱？ | 指定规格/策略档位，非常规绑死单机 |
| 钉钉数字员工与应用分开？ | 分开；钉钉挂数字员工，应用只提供能力 |
| Agent 执行权限？ | 独立第三轨：使用权限 ∩ 应用工具策略 ∩ 身份 ∩ 沙箱 ∩ 配额 |
